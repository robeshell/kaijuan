## 1. 结论（先读）

**先分析展示方式**：生成图谱时，模型先根据书名、作者、大纲和少量正文给出「展示方案」，包括叙述特征、建议首次视图和是否显示地点顺序。之后逐章抽取时，这份方案只用来调整抽取侧重。UI 导航顺序固定，模型只决定首次打开哪个已有视图；老图谱没有方案字段时默认人物视图。

**家族树**：数据层先解决**关系方向**问题（见 §4）；抽取 prompt 固定方向后，生成末尾再用原文证据批量复核代际边。家族树全程以 `entityId` 连接，只接收父母/祖辈→子女的代际亲属边；兄弟姐妹、叔伯姨舅、表亲等旁系关系保留在关系图，不进入上下层级。组织树后置。

**地图**：不做真地图（虚构地点无坐标、模型坐标不可靠、渲染成本高）。地点索引可显示**首次出现顺序**，必须明确这不是地理路线；地图形态由用户后续设计。

| 决策 | 取值 | 理由 |
|------|------|------|
| 生成前分析 | **生成前确认窗口**：窗口内分析展示方案，显示五项特征和推荐默认视图；用户确认或改选后开始逐章抽取。分析失败时可重试、跳过或取消 | 用户可感知、可干预；方案只影响展示 |
| 方案存储 | 图谱包内 `narration` 段（随生成落盘、随 WebDAV 备份、随删除）；合集书**按著作出方案**（与图谱范围一致） | 与图谱同生命周期，无独立文件 |
| 方向约定 | 方向性关系类型（亲属/隶属/效力/师徒/追随）prompt 固定方向；合并 key **不排序**（保持方向）；无向类型 key 排序去重（增强项，后置） | 树视图必须稳定方向；力导向图无方向要求 |
| 树边 | 仅 **代际亲属**（父母/祖辈→子女）；兄弟、姨母、表亲、婚配等不进父子层级 | `亲属` 是语义大类，不等于树边；旁系关系硬塞成父子会制造伪层级 |
| 渲染 | **CustomPainter 自绘** + InteractiveViewer（缩放/平移）+ 点击命中弹实体卡；pub 无成熟组织架构图库 | 连线架构图形态 = 政府机关架构图（自上而下框+连线） |
| 老图谱 | 无方向保证 → 树视图**不启用**（入口隐藏、不提示，行为与现状一致）；不做方向推断 | 推断不可靠，避免误导 |
| 地图 | 不做真地图；地点首次出现顺序（非路线） | 见上 |

## 2. 目标与非目标

### 做

- **生成前展示方案**：一次全书级调用输出 `AiNarrationPlan`（§3 契约）；方案可见（§7）。
- **调整抽取侧重**：方案按特征调整抽取提示（§3.3）——所有书都允许
  `organization`，组织博弈型只加强组织与隶属边的召回；地理叙事型地点描述加码。
- **方向性关系约定**：prompt 固定方向性类型方向（§4）；此为树的地基。
- **家族树**：数据（person + 经证据复核的代际亲属边）→ ID 构建（根/森林/环/多父/孤岛，§5.2）→ 连线架构图渲染（§5.3）。
- **地点叙事顺序**：地理驱动书的地点首次出现视图（§6）。

### 不做（本能力内）

- **组织索引**：`organization` 作为独立实体类型展示，不再混入人物；当前采用可搜索、可排序的组织索引，不能把“组织博弈”错误映射为家族树。组织层级图只有在隶属/效力边具备足够覆盖率时再单独引入。
- **完整夫妻并列树节点**：当前只在已有树节点的卡片旁显示配偶信息，不把婚配关系画成父子层级或独立的同层双节点。
- 树视图收起/展开子节点、节点拖拽、动画、LOD。
- **真地图**：坐标不可靠 + 渲染成本；形态用户后续设计，本页只留文字版。
- 老图谱关系方向推断。
- 展示方案用于对话上下文 / 阅读正文高亮（沿用 ai-graph.md「不做」）。

## 3. 生成前展示方案

### 3.1 契约

```jsonc
{
  "features": { "eventDriven": 0.8, "characterEnsemble": 0.9,
                "organization": 0.6, "geography": 0.3, "essay": 0.1 },
  "defaultView": "persons|locations|events|organizations|things|graph|family_tree",
  "viewOrder": ["family_tree", "persons", "events", "graph"],
  "wantMap": false
}
```

- 五维特征**各自独立 0–1**，不必归一；特征语义：eventDriven 事件驱动 / characterEnsemble 人物群像 / organization 组织博弈 / geography 地理叙事 / essay 散文随笔。
- `defaultView` / `viewOrder` 取值来自 persons/locations/events/organizations/things/graph/family_tree；旧缓存中的 `org_tree` 迁移为 `organizations`。`viewOrder` 仅作兼容与分析记录，正式导航始终按固定“索引（人物/地点/事件/组织/事物）+ 探索（关系图/家族树）”展示。推荐默认视图只在保存图谱经证据校验后确有对应实体或关系时采用；若该视图为空，首次打开按固定导航顺序回退到第一个非空视图，全部为空时回退到人物空状态。
- **老图谱**（无 narration 段）→ `defaultView = persons`、viewOrder = 现状固定顺序 → 行为与现状完全一致。

### 3.2 流程

```text
点「生成图谱」/「重新生成」→ 方案确认弹窗：
  弹窗内第 0 步：方案调用（书名/作者 + 大纲 + 正文抽样，1 次；loading「正在分析本书的展示方案…」）
    → 成功：展示五维特征条 + 推荐默认视图（可改选，仅改变首次视图）→ 用户确认
    → 失败：弹窗提示「展示方案分析失败」+ 重试 / 取消（不再静默吞掉）
  弹窗内并行加载「图谱正文范围」：自动过滤（metadata/appendix 词表 + spine 去重）后的扁平节列表，
    每行显示目录名或文档标题，不能把 EPUB 内部 href/文件路径暴露给用户；无标题时回退「第 N 节」；
    用户可点整行勾选/排除，也可「全选 / 清空」（如 中文版序言/导读/出版说明 等词表漏网的辅文）；
    弹窗内容区独立滚动并始终显示滚动条与「已选 N / M 节」，全排除时不能开始生成
  确认后 → 带着用户确认的方案 + 排除节集合继续逐章抽取（方案写入图谱包 narration 段）
增量续跑（已有 narration）不弹窗，沿用现有方案；「重新分析展示方案」（生成后方案卡）单独重跑并覆盖 narration 段（不动实体/关系）
```

- **切片口径（single source of truth）**：弹窗显示的节列表 = `controller.graphSectionChoices(work)` = 生成时 `_graphSectionsForWork(work)` 的同一份 deduped 结果；用户排除按 `AiBookSectionSlice.index` 记录，生成时 `excludeGraphSections` 应用——两处永远同一源头，杜绝「弹窗看的和生成的不一致」。范围选择只呈现可生成的正文叶子，不复刻目录树；文件内合订的作品边界已由 `work` 决定，弹窗只负责在该作品内选择章节。
- **正文切片 = 按目录（TOC）读**（用户拍板，`_loadBookGraphPlainTextCached` `toc: true`）：节 = 书的目录单元（出版说明/中文版序言/第一章…），弹窗显示可读标题而非 `Text/Section0022.html` 文件路径；证据跳转落到单元起始 spine（章级，图谱本就是章级产物）；无可用 TOC 的书在 JS 内自动回退按 spine 切。
- **前置文本单元**：JS 把不在 TOC 的前置文本归入「目录」标签且**不带 `~` nav 标记**（真实 TOC 条目才带）——这样 Dart 的 metadata 过滤（目录 精确词）能删掉它，不会被 nav 豁免放过。
- 自动过滤只做保守词表（前缀/精确匹配），**不做包含匹配**（曾因激进规则误伤《沉默的大多数》，见 [[graph-entity-scope]]）；组合标题（中文版序言/译者的话/本书介绍…）漏网是设计内行为——交给用户在弹窗手动排除，不再猜词表。
- 合集书：方案调用范围 = 所选择的著作（与逐章抽取范围一致），弹窗节列表也按著作范围。
- 方案调用失败时窗口显示失败状态；用户可以重试、跳过方案后继续生成，或取消。该失败不计入后续章节抽取的失败次数。

### 3.3 按方案调整抽取侧重

| 特征 | 阈值 | 调整方式 |
|------|------|----------|
| organization | 所有取值 | `organization` 始终是合法实体类型，不能因第 0 步低分而关闭 |
| organization | ≥ 0.5 | 额外强调组织/势力/家族实体与隶属边（隶属/效力/追随）的完整召回 |
| geography | ≥ 0.5 | 地点 description 加码：方位、与其他地点的相对关系 |
| essay | ≥ 0.5 | scope 判定加严提示（引用句式硬规则已有，见 ai-graph-service `_applyScopeHardRules`，此处仅加权重不新增规则） |

- 方案只调整召回重点，不改变实体结构的能力边界。生成前分析只是展示与侧重建议，
  不能成为事实抽取的门禁。

## 4. 方向性关系约定（数据层，树的地基）

### 4.1 现状问题

v2 合并 key 为 `$sourceId\u0000$targetId\u0000$type`，方向性关系按 prompt 约定方向；家族树进入渲染前仍会去除反向镜像与断环，避免模型偶发翻转污染结构。

### 4.2 约定

关系类型分两档：

| 档 | 类型（默认词表） | 处理 |
|----|------------------|------|
| **有向（进树候选）** | 亲属、师徒、隶属、效力、追随 | prompt 固定方向（下表）；合并 key 保持方向不排序 |
| **无向** | 婚配、同盟、敌对、信任、爱慕、同僚、共事、协助、举荐、更替、弹劾、庇护、提携、忌惮、调停、相关(fallback) | 不约束方向；key 排序去重（增强项，可后置） |

有向类型方向表（prompt 明示）：

| 类型 | source | target |
|------|--------|--------|
| 亲属 | 长辈（父/母/祖辈） | 晚辈（子/女/孙辈） |
| 师徒 | 师父 | 徒弟 |
| 隶属 | 上级 / 上级组织 | 下级 / 成员 |
| 效力 | 组织 / 君主（被效力方） | 成员（效力者） |
| 追随 | 被追随者（首领） | 追随者 |

- prompt 追加：「关系类型为 亲属/师徒/隶属/效力/追随 时，source 必须是 长辈/师父/上级/被效力方/被追随者，target 必须是 晚辈/徒弟/下级/效力者/追随者，方向颠倒即为错误」。
- 方向颠倒无法完全由程序判定，靠人工标注样本抽查（§8 N1 验收）。
- **v1 树边只取「亲属」**；组织树落地时再取 隶属/效力/追随（届时按实际数据复核方向表）。

### 4.3 老图谱

- 方向无保证 → 树视图对老数据**不启用**：family_tree 入口隐藏、**不提示**（保持老图谱行为与现状完全一致；树的地基是数据方向，无法从旧数据推断）。
- 不推断方向、不迁移旧数据（canonical 名只增不删原则延续）。

## 5. 家族树视图

### 5.1 数据

- 节点：person 实体（scope = setting；reference 实体不进树）。
- 树边：亲属（长辈→晚辈）。婚配/同盟/敌对等无向边不进树（实体卡关系列表照常展示）。
- **边称谓**：`AiGraphRelation.kin`（具体称谓，如 父子/夫妻/兄弟，抽取提示输出；旧图谱无此字段）。家族树视图在折线水平段中点画称谓标签，空称谓不画；`kin` 也显示在实体卡关系列表。
- **配偶信息**：婚配关系不进入父子层级，也不绘制成父子连线；已经进入血缘树的人物卡可以旁挂显示配偶、皇后或妃嫔等称谓。只有婚配、没有代际亲属边的人物不单独占一个树节点，仍可从伴侣卡和普通关系图查看。
- 同辈亲属（兄弟/姐妹）：不构成树边，实体卡关系列表展示。

### 5.2 构建

1. 由 person 实体 + 亲属有向边建图。
2. **根** = 入度 0 的节点；多根 → **森林**，每棵树一个画布分区（横向并排或切换）。
3. **环**：Kahn 残余检测；保留**证据最多**的环边（并列 firstSection 早者），其余被打断的边端点进「关系复杂」名单（被打断的关系经名单点击实体卡可见）。
4. **多父**（入度 > 1）：保留**证据最多**的父边（evidence 数最多，并列时 firstSection 早者胜），其余进「关系复杂」。
5. **层级** = 从根到节点的最长路径深度（自上而下第 1 层 = 根）。
6. **孤岛**（无树边实体）→ 折叠为「未入树 N 人」列表行，点击展开（复用实体列表行样式）。

### 5.3 渲染（连线组织架构图）

- **CustomPainter 自绘**：节点 = 圆角矩形（实体名，复杂节点加警示图标 + 红边），边 = 自上而下折线；pub 无成熟组织架构图库（graphview 的 RenderCustomLayoutBox 吞节点 tap，已试退）。
- 布局：自上而下、同级横向均布；**画布横向恒铺满视口**——窄树把同级间距撑开（上限 264）摊满全宽，宽树保底间距 176（= 2 × 节点宽，父卡居中不压中间子卡）并由 InteractiveViewer 平移查看；画布高 = 层级数 × 层高。
- **InteractiveViewer（`constrained:false` + `boundaryMargin:infinity`）**：拖拽平移、滚轮/捏合缩放；打开时 post-frame 自动 fit 整树居中放大铺满（浅树不被缩成缩略图），之后用户接管缩放。Stack 自绘 Positioned 节点 → Flutter 原生命中测试 → 点击天然可靠。
- 点击命中节点 → 复用现有实体卡（描述/别名/关系/证据，点证据跳原文）。
- 当前明确**不做**：收起/展开子节点、节点拖拽改布局、把配偶绘制成同层双节点、动画和按缩放级别减少细节。

## 6. 地图文字版

- 触发：方案 `geography ≥ 0.5`（非地理书不显示）。
- 地点首次出现视图（locations 视图内，geography ≥ 0.5 触发）：排序 key = `firstSection` 再按首条已定位证据的 `progressInSection`；地点以 pills 展示，分隔符不使用路线箭头，并标明“非地理路线”。点击进入实体卡，出现次数按涉及章节数统计。location 仅限地理地点，船只/机构/组织不算 location。
- 真地图形态用户后续设计；本页只保证文字版数据与入口，不预留地图渲染接口。

## 7. 交互（图谱 Tab 增量）

```text
生成前：点击后原图谱页立即进入「正在准备图谱…」并防重复提交；手机先收起输入法，再在同一 root navigator 上打开第二层范围 Sheet，平板/展开折叠屏使用锚定到 trailing/bottom 子屏的 Dialog。弹层内并行准备展示方案与正文范围，但相同正文语料的 WebView 抽取必须合并为一个进行中请求；loading「正在分析本书的展示方案… / 正在读取内容范围…」→ 方案展示（特征条 + 默认视图改选）+ 图谱正文范围手动切片 → 确认后由 controller 接管，原页面无缝切为章节批次进度；取消、失败或弹层关闭都要清除 preparing 状态并恢复可操作入口。
已生成：视图切换（SegmentedButton）直接显示，**无方案摘要卡**（用户拍板：展示方案用户不关心，不输出在知识图谱区域；数据仍驱动默认视图与入口顺序）
导航：固定“索引（人物/地点/事件/组织）+ 探索（关系图/家族树）”；默认优先选中方案 defaultView，最终结果为空则按上面的结果感知规则回退。只要图谱结果对象存在，切换器就在非生成状态持续可见，即使当前分类、全部主实体或全部结果为空，也不能把读者困在某个“暂无实体”页面；空分类只替换内容区，不移除导航、重新生成或删除入口；
  入口全保留不隐藏（不藏功能）；family_tree 入口仅在有方向保证的新图谱显示
点击家族树节点 → 实体卡（复用）；点证据跳原文并关面板（沿用 ai-graph.md）
老图谱：无 narration → 无 family_tree 入口，行为与现状一致
```

- 展示方案用于默认视图和抽取侧重；生成前确认窗口会显示推荐结果并允许修改。生成后的图谱页不额外常驻展示五项特征。
- 方案与防剧透：展示方案是全书级元信息，与实体内容无关，不参与防剧透过滤。

## 8. 落地切片与验收

### N1 — 方向约定 + 方案契约（数据层与模型层）

- 抽取提示增加方向约定；用 5 章人工标注样本复跑，格式合法率和引文定位率不能下降（沿用 ai-graph.md §5.7）。
- 方案调用 + `narration` 段模型/落盘/读取 + 契约校验 + 失败后由用户选择重试、跳过或取消。
