## 1. 结论（先读）

**展示方案驱动**：生成图谱时，模型第 0 步（全书级一次调用：书名/作者 + 大纲 + 正文抽样）输出「展示方案」（多维叙述特征 + 推荐默认视图 + 视图排序 + 是否要地图），之后逐章抽取按方案反哺。UI 默认视图与入口顺序由方案决定；老图谱无方案字段 → 默认人物视图（现状不变，兼容）。

**家族树**：数据层先解决**关系方向**问题（现状方向不稳定，见 §4），抽取 prompt 固定方向性关系方向；家族树 = person 实体 + 亲属边（长辈→晚辈），用**连线组织架构图**形态（自绘）渲染。组织树后置。

**地图**：不做真地图（虚构地点无坐标、模型坐标不可靠、渲染成本高）。先做**文字版地点链**；地图形态由用户后续设计。

| 决策 | 取值 | 理由 |
|------|------|------|
| 第 0 步接入 | **生成前确认弹窗**：弹窗内跑方案调用（loading「正在分析本书的展示方案…」）→ 展示五维特征 + 推荐默认视图，用户确认或改选后开始逐章抽取；**失败在弹窗内提示 + 重试/取消（不再静默）** | 用户可感知、可干预（默认视图在生成前定）；方案只影响展示 |
| 方案存储 | 图谱包内 `narration` 段（随生成落盘、随 WebDAV 备份、随删除）；合集书**按著作出方案**（与图谱范围一致） | 与图谱同生命周期，无独立文件 |
| 方向约定 | 方向性关系类型（亲属/隶属/效力/师徒/追随）prompt 固定方向；合并 key **不排序**（保持方向）；无向类型 key 排序去重（增强项，后置） | 树视图必须稳定方向；力导向图无方向要求 |
| 树边（v1） | 仅 **亲属**（长辈→晚辈）；婚配/同盟等无向类型不进树 | 婚配无方向，配偶并列摆放是独立难题 |
| 渲染 | **CustomPainter 自绘** + InteractiveViewer（缩放/平移）+ 点击命中弹实体卡；pub 无成熟组织架构图库 | 连线架构图形态 = 政府机关架构图（自上而下框+连线） |
| 老图谱 | 无方向保证 → 树视图**不启用**（入口隐藏、不提示，行为与现状一致）；不做方向推断 | 推断不可靠，避免误导 |
| 地图 | 不做真地图；文字版地点链 | 见上 |

## 2. 目标与非目标

### 做

- **第 0 步展示方案**：一次全书级调用输出 `AiNarrationPlan`（§3 契约）；方案可见（§7）。
- **反哺抽取**：方案按特征分支调整抽取 prompt（§3.3）——组织博弈型要求 `organization` 实体 + 隶属边；地理叙事型地点描述加码；散文随笔型强化 scope 降级。
- **方向性关系约定**：prompt 固定方向性类型方向（§4）；此为树的地基。
- **家族树**：数据（person + 亲属边）→ 构建（根/森林/环/多父/孤岛，§5.2）→ 连线架构图渲染（§5.3）。
- **地图文字版**：地理驱动书的地点链视图（§6）。

### 不做（本能力内）

- **组织树**：后置。需 `organization` 实体先稳定（v1 抽取不生成该类型），复用同一树组件与方向约定再补。
- **婚配进树**（配偶并列摆放）：实体卡关系列表照常展示即可。
- 树视图收起/展开子节点、节点拖拽、动画、LOD。
- **真地图**：坐标不可靠 + 渲染成本；形态用户后续设计，本页只留文字版。
- 老图谱关系方向推断。
- 展示方案用于对话上下文 / 阅读正文高亮（沿用 ai-graph.md「不做」）。

## 3. 展示方案（第 0 步）

### 3.1 契约

```jsonc
{
  "features": { "eventDriven": 0.8, "characterEnsemble": 0.9,
                "organization": 0.6, "geography": 0.3, "essay": 0.1 },
  "defaultView": "persons|locations|events|graph|family_tree|org_tree",
  "viewOrder": ["family_tree", "persons", "events", "graph"],
  "wantMap": false
}
```

- 五维特征**各自独立 0–1**，不必归一；特征语义：eventDriven 事件驱动 / characterEnsemble 人物群像 / organization 组织博弈 / geography 地理叙事 / essay 散文随笔。
- `defaultView` / `viewOrder` 取值来自 UI 已有视图（persons/locations/events/graph）+ family_tree / org_tree（org_tree 在组织树落地前不产出）。
- 模型给不出稳定 viewOrder 时允许只给 defaultView，程序补 viewOrder = defaultView 优先 + 其余按固定顺序。
- **老图谱**（无 narration 段）→ `defaultView = persons`、viewOrder = 现状固定顺序 → 行为与现状完全一致。

### 3.2 流程

```text
点「生成图谱」/「重新生成」→ 方案确认弹窗：
  弹窗内第 0 步：方案调用（书名/作者 + 大纲 + 正文抽样，1 次；loading「正在分析本书的展示方案…」）
    → 成功：展示五维特征条 + 推荐默认视图（可改选，viewOrder 随之重排）→ 用户确认
    → 失败：弹窗提示「展示方案分析失败」+ 重试 / 取消（不再静默吞掉）
  弹窗内并行加载「图谱正文范围」：自动过滤（metadata/appendix 词表 + spine 去重）后的节列表，
    用户可取消勾选排除（如 中文版序言/导读/出版说明 等组合标题前缀词表漏网的辅文）；
    显示「已选 N / M 节」，全排除时生成报错「请至少保留一节正文」
  确认后 → 带着用户确认的方案 + 排除节集合继续逐章抽取（方案写入图谱包 narration 段）
增量续跑（已有 narration）不弹窗，沿用现有方案；「重新分析展示方案」（生成后方案卡）单独重跑并覆盖 narration 段（不动实体/关系）
```

- **切片口径（single source of truth）**：弹窗显示的节列表 = `controller.graphSectionChoices(work)` = 生成时 `_graphSectionsForWork(work)` 的同一份 deduped 结果；用户排除按 `AiBookSectionSlice.index` 记录，生成时 `excludeGraphSections` 应用——两处永远同一源头，杜绝「弹窗看的和生成的不一致」。
- **正文切片 = 按目录（TOC）读**（用户拍板，`_loadBookGraphPlainTextCached` `toc: true`）：节 = 书的目录单元（出版说明/中文版序言/第一章…），弹窗显示可读标题而非 `Text/Section0022.html` 文件路径；证据跳转落到单元起始 spine（章级，图谱本就是章级产物）；无可用 TOC 的书在 JS 内自动回退按 spine 切。
- **前置文本单元**：JS 把不在 TOC 的前置文本归入「目录」标签且**不带 `~` nav 标记**（真实 TOC 条目才带）——这样 Dart 的 metadata 过滤（目录 精确词）能删掉它，不会被 nav 豁免放过。
- 自动过滤只做保守词表（前缀/精确匹配），**不做包含匹配**（曾因激进规则误伤《沉默的大多数》，见 [[graph-entity-scope]]）；组合标题（中文版序言/译者的话/本书介绍…）漏网是设计内行为——交给用户在弹窗手动排除，不再猜词表。
- 合集书：方案调用范围 = 所选择的著作（与逐章抽取范围一致），弹窗节列表也按著作范围。
- 方案调用失败**不阻断**生成，也不记入失败次数（与章节抽取失败分类重试互不影响）。

### 3.3 反哺（抽取 prompt 分支）

| 特征 | 阈值 | 反哺动作 |
|------|------|----------|
| organization | ≥ 0.5 | 抽取 prompt 允许并鼓励 `organization` 类型实体 + 隶属边（隶属/效力/追随）；实体卡类型色扩展 |
| geography | ≥ 0.5 | 地点 description 加码：方位、与其他地点的相对关系 |
| essay | ≥ 0.5 | scope 判定加严提示（引用句式硬规则已有，见 ai-graph-service `_applyScopeHardRules`，此处仅加权重不新增规则） |

- 反哺只改抽取 prompt 文本，不改校验/合并管线；未激活分支走现状 prompt。

## 4. 方向性关系约定（数据层，树的地基）

### 4.1 现状问题

合并 key 为 `$source\u0000$target\u0000$type`（`ai_graph_service.dart`），**未排序、未约定方向**——「A 是 B 之父」可能存成 A→B 也可能 B→A，纯看模型输出。对力导向图无影响，对树致命。

### 4.2 约定

关系类型分两档：

| 档 | 类型（默认词表） | 处理 |
|----|------------------|------|
| **有向（进树候选）** | 亲属、师徒、隶属、效力、追随 | prompt 固定方向（下表）；合并 key 保持方向不排序 |
| **无向** | 婚配、同盟、敌对、信任、爱慕、同僚、共事、协助、举荐、更替、弹劾、庇护、提携、忌惮、调停、相关(fallback) | 不约束方向；key 排序去重（增强项，可后置） |

有向类型方向表（prompt 明示）：

| 类型 | source | target |
|------|--------|--------|
| 亲属 | 长辈（父/母/祖辈） | 晚辈（子/女/孙辈） |
| 师徒 | 师父 | 徒弟 |
| 隶属 | 上级 / 上级组织 | 下级 / 成员 |
| 效力 | 组织 / 君主（被效力方） | 成员（效力者） |
| 追随 | 被追随者（首领） | 追随者 |

- prompt 追加：「关系类型为 亲属/师徒/隶属/效力/追随 时，source 必须是 长辈/师父/上级/被效力方/被追随者，target 必须是 晚辈/徒弟/下级/效力者/追随者，方向颠倒即为错误」。
- 方向颠倒无法程序判定，靠 golden set 抽样核对（§8 N1 验收）。
- **v1 树边只取「亲属」**；组织树落地时再取 隶属/效力/追随（届时按实际数据复核方向表）。

### 4.3 老图谱

- 方向无保证 → 树视图对老数据**不启用**：family_tree 入口隐藏、**不提示**（保持老图谱行为与现状完全一致；树的地基是数据方向，无法从旧数据推断）。
- 不推断方向、不迁移旧数据（canonical 名只增不删原则延续）。

## 5. 家族树视图

### 5.1 数据

- 节点：person 实体（scope = setting；reference 实体不进树）。
- 树边：亲属（长辈→晚辈）。婚配/同盟/敌对等无向边不进树（实体卡关系列表照常展示）。
- **边称谓**：`AiGraphRelation.kin`（具体称谓，如 父子/夫妻/兄弟，抽取 prompt 输出；旧图谱无此字段）。家族树视图在折线水平段中点画称谓标签（小圆角 chip，9px），空称谓不画；kin 亦存于实体卡关系列表。
- 同辈亲属（兄弟/姐妹）：不构成树边，实体卡关系列表展示。

### 5.2 构建

1. 由 person 实体 + 亲属有向边建图。
2. **根** = 入度 0 的节点；多根 → **森林**，每棵树一个画布分区（横向并排或切换）。
3. **环**：Kahn 残余检测；保留**证据最多**的环边（并列 firstSection 早者），其余被打断的边端点进「关系复杂」名单（被打断的关系经名单点击实体卡可见）。
4. **多父**（入度 > 1）：保留**证据最多**的父边（evidence 数最多，并列时 firstSection 早者胜），其余进「关系复杂」。
5. **层级** = 从根到节点的最长路径深度（自上而下第 1 层 = 根）。
6. **孤岛**（无树边实体）→ 折叠为「未入树 N 人」列表行，点击展开（复用实体列表行样式）。

### 5.3 渲染（连线组织架构图）

- **CustomPainter 自绘**：节点 = 圆角矩形（实体名，复杂节点加警示图标 + 红边），边 = 自上而下折线；pub 无成熟组织架构图库（graphview 的 RenderCustomLayoutBox 吞节点 tap，已试退）。
- 布局：自上而下、同级横向均布；**画布横向恒铺满视口**——窄树把同级间距撑开（上限 264）摊满全宽，宽树保底间距 176（= 2 × 节点宽，父卡居中不压中间子卡）并由 InteractiveViewer 平移查看；画布高 = 层级数 × 层高。
- **InteractiveViewer（`constrained:false` + `boundaryMargin:infinity`）**：拖拽平移、滚轮/捏合缩放；打开时 post-frame 自动 fit 整树居中放大铺满（浅树不被缩成缩略图），之后用户接管缩放。Stack 自绘 Positioned 节点 → Flutter 原生命中测试 → 点击天然可靠。
- 点击命中节点 → 复用现有实体卡（描述/别名/关系/证据，点证据跳原文）。
- v1 明确**不做**：收起/展开子节点、节点拖拽改布局、配偶并列、动画、LOD。

## 6. 地图文字版

- 触发：方案 `geography ≥ 0.5`（非地理书不显示）。
- 「地点链」视图（locations 视图内，geography ≥ 0.5 触发）：**一条按出现顺序串成的链**——排序 key = `firstSection` 再按首条已定位证据的 `progressInSection`（章内多个地点能排出真实先后）；地点用 **→ 箭头 pills** 连接（点击进实体卡，出现次数 >1 标 ×N）。**不显示章头**：图谱章节是 spine 口径，与用户目录（TOC 口径）对不上，显示反而误导。location 定义加严（反哺 prompt）：仅限地理地点，船只/机构/组织不算 location。
- 真地图形态用户后续设计；本页只保证文字版数据与入口，不预留地图渲染接口。

## 7. 交互（图谱 Tab 增量）

```text
生成前：弹窗内 loading「正在分析本书的展示方案…」→ 方案展示（特征条 + 默认视图改选）+ 图谱正文范围手动切片 → 确认后开始；生成中进度照常章节批次
已生成：视图切换（SegmentedButton）直接显示，**无方案摘要卡**（用户拍板：展示方案用户不关心，不输出在知识图谱区域；数据仍驱动默认视图与入口顺序）
SegmentedButton：顺序 = 方案 viewOrder，默认选中 defaultView；
  入口全保留不隐藏（不藏功能）；family_tree 入口仅在有方向保证的新图谱显示
点击家族树节点 → 实体卡（复用）；点证据跳原文并关面板（沿用 ai-graph.md）
老图谱：无 narration → 无 family_tree 入口，行为与现状一致
```

- 展示方案仅作内部驱动（默认视图/入口顺序/反哺分支），不在图谱 Tab 展示；生成前弹窗仍可改默认视图（重新生成时弹窗重跑方案）。
- 方案反哺与防剧透：展示方案是全书级元信息，与实体内容无关，不参与防剧透过滤。

## 8. 落地切片与验收

### N1 — 方向约定 + 方案契约（数据层与模型层）

- 抽取 prompt 加方向约定；5 章 golden set 复跑：schema 合法率 / quote 定位率不回归（ai-graph.md §5.7 指标沿用）。
- 方案调用 + `narration` 段模型/落盘/读取 + 契约校验 + 失败静默降级。
- 验收：老图谱打开无 narration → 默认人物视图、行为与现状逐项一致；新生成图谱 narration 段存在且校验通过；亲属边方向抽样核对（父→子）正确率 ≥ 90%（golden set）。

### N2 — 方案可见 + 反哺

- 进度文案；反哺 prompt 三分支。
- 验收：散文书（essay 高）scope 降级不回归（沿用硬规则测试）；组织博弈书抽取含 `organization` 实体与隶属边。

### N3 — 家族树（数据 → 构建 → 渲染）

- 树构建：根/森林/环打断/多父/孤岛折叠；单元测试覆盖环与多父样例。
- CustomPainter 渲染 + InteractiveViewer + 点击命中弹实体卡。
- 验收：血亲树方向正确；环书不崩且打断关系可查；未入树折叠数正确；>200 节点树滚缩流畅（桌面 + 移动）。

### N4 — 地图文字版

- 地点链视图（geography ≥ 0.5 触发）。
- 验收：地理驱动书显示地点链且顺序 = 叙事顺序；非地理书不显示入口。

## 10. 开放问题

- **组织树**：`organization` 实体与家族树组件已就位，组织树视图本身待做（需先用组织博弈书实测 organization 实体抽取质量）；「效力」边方向（被效力方→效力者）在组织树实施时按实际数据复核。
- **婚配进树**：配偶并列摆放布局，独立难题，后置。
- **无向关系 key 排序去重**：防 A-B / B-A 分裂（现状全不排序），增强项。
- **地图形态**：用户后续设计；文字版地点链已落地（locations 视图，geography ≥ 0.5 触发）。
