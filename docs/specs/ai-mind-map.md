## 1. 定位

图书思维导图表达章节主题、论点和层级摘要。它与知识图谱分属两个业务模块：知识图谱以实体、关系、证据和身份消歧为中心；思维导图以一份冻结正文范围内的主题层级为中心。两者不得共用业务模型、缓存或视图状态。

普通聊天继续支持 Mermaid 和其他富内容图表。聊天图表是一次回答的展示内容，不得作为图书思维导图的事实来源、缓存格式或恢复输入。

## 2. 产品入口与范围

- 独立 Workflow 不等于独立页签。「本书 AI」不设置思维导图 Tab；用户在对话中说“当前章/本章”时冻结当前章，说“这本书/全书”时冻结整本出版物，随后直接路由到 `BookMindMapWorkflow`。生成进度、停止、失败、重试和完成后的原生交互图都属于该对话轮次，不向聊天 Agent 发送长期任务提示词。
- 发起轮次时由 App 冻结 `contentHash`、可选 `workKey`、作品标题和章节范围；当前翻页不改变运行中的范围。“当前章”必须直接冻结 Foliate 当前文档正文、章标题和物理定位；不得先抽取整书逻辑章节，再假设阅读器 section 序号与逻辑语料的 `sourceSectionIndex` 一定同源。自然语言中的明确范围就是用户确认，不再弹出独立范围选择器。
- “生成本章思维导图”快捷入口冻结当前章；用户明确说“这本书/整本书/全书”时冻结整本出版物，不先运行作品识别，也不为同一请求重复提取整书正文。当前章纯文本必须保留可见标题、段落、列表之间的换行，不能因 DOM `textContent` 拼接而丢失结构。本章只有一个冻结内容单元时，在单批预算内必须保留全文并一次结构化生成节点树，不得沿用整书的逐章短采样或 batch/reduce；只有单章自身超过单批安全预算才允许头、中、尾保序采样。整书字符预算必须跨章节均衡，不能让后部章节消失。
- 打开本书 AI 面板本身不得预先触发作品结构识别。结构识别只在普通对话首次需要作品作用域或用户进入知识图谱时懒加载；明确的本章/全书思维导图请求直接进入自己的冻结范围。对话输入通过平台 IME 提交时，清空草稿必须延迟到当前 frame 结束，不能在文本输入回调或语义刷新期间同步修改 `TextEditingController`。
- “本章”或“这本书/全书”本身就是完整范围确认，产品不提供章节勾选器或二次范围弹窗。整书使用思维导图自己的确定性正文策略：可以复用已经存在的章节标题事实，但不得为此先运行作品识别，也不得复用知识图谱“全部展示、等待用户确认”的范围语义。版权、目录、参考文献、附录、索引、名家/媒体推荐与点评、出版说明与出版始末、版本纪事、书评/印象记、导读/读法等明确出版外围材料，以及正文等同于标题的空容器单元，在进入模型前自动移除。作者自己的前言、自序、后记、结语可能承载全书主张，不得仅凭“序/后记”字样或字符数删除。默认排除标题在设置「高级 AI 规则 / 思维导图内容范围」中可见、可扩充；每行是全标题匹配模式，只允许 `*` 表示任意字符，其余字符按字面处理，禁止接受任意正则。空列表表示关闭标题排除，但不关闭空容器和正文内版权信号检查。
- 自然语言路由只识别带生成动作的请求，例如“生成/制作/画/整理成思维导图”或“我想看看本书思维导图”。仅讨论已有导图的内容、失败、样式或生成方法时继续作为普通对话，不得自动发起付费 Workflow。
- 首次生成、重新生成和恢复 checkpoint 都使用相同的范围指纹。范围变化后旧 checkpoint 不得混入新任务。

## 3. 数据契约

落盘事实为 `AiBookMindMap`，不保存 Mermaid 源码：

```text
AiBookMindMap
  version / contentHash / workKey / createdAt / model
  scopeSectionIndices / scopeFingerprint / contentKind / layout
  nodes[]

AiBookMindMapNode
  nodeId / parentId / order / level
  title / summary / evidence[]

AiBookMindMapEvidence
  sectionIndex / quote / progressInSection / spanResolved
```

- 节点使用扁平数组。`nodeId` 在 App 校验后按确定性前序重新分配，`parentId` 只引用同一产物内节点。
- 完成产物以结构化附件随对话消息持久化，同一会话可同时保留多个章节与全书思维导图；不得用仅按 `contentHash + workKey` 的单槽缓存覆盖旧对话结果。
- 只有一个根节点；无环、无孤儿、`level = parent.level + 1`、同父 `order` 唯一且连续。
- `title` 是短主题标签，`summary` 是用户直接阅读的正文总结；每个节点都必须有摘要，且摘要不能只复述标题或使用“主要内容”“相关内容”等占位话术。根摘要概括所选范围的中心结论，其他节点按正文自然组织论点、叙事阶段、原因、事实、例子、影响或结论。节点数量、同级分支数量和层级深度由实际内容决定，App 不设置产品配额，不为凑数补节点，也不因固定上限删除内容。模型输出仍需经过摘要有效性、合法树结构、范围覆盖、证据范围和引文定位校验。
- 引文是可选的跳回原文增强信息：能在所选正文中定位时标为 `spanResolved=true` 并提供跳转；缺少或无法定位的引文不阻断摘要节点或整棵树，也不得被伪造为精确跳转。
- `evidence.sectionIndex` 是 1-based EPUB/Foliate 物理 section 坐标，同一章内的多条引文可以合法地拥有相同值；真正的章内位置由 `progressInSection` 区分。详情页不得把单章导图的所有出处只重复显示成同一个“第 N 节”：单 section 范围显示“本章 · 约 N% 处”，多 section 范围显示“第 N 节 · 约 N% 处”，跳转仍同时使用 section 与章内进度。

## 4. 确定性 Workflow

```text
App 冻结书籍/作品/章节范围
  → 单内容单元：一次 AiWorkflowModelSession.completeJson 生成树
  → 多内容单元：章节均衡采样与稳定 batch
  → 逐 batch 调用 AiWorkflowModelSession.completeJson
  → 原子写入 checkpoint（已完成 batch + 中间摘要）
  → 最终结构化归并
  → Schemantic schema + App 业务校验
  → App 规范化 nodeId/层级/证据
  → App 按内容类型与拓扑选择布局
  → 原子保存 AiBookMindMap，删除 checkpoint
```

- `BookMindMapWorkflow` 自己不持有 Provider、Genkit 类型、UI 或 WebDAV 客户端。模型 I/O 只经 `AiWorkflowModelSession.completeJson`。
- 开卷拥有 `AiRunOrchestrator`、预算、取消、超时、范围、重试、checkpoint、存储和 UI 状态。暂不使用 Genkit `defineFlow` / Agent；Genkit 只负责 Provider 归一化、structured output、Schema 和 trace。
- DeepSeek 只接受原生 `json_object`，隔离 adapter 把锁版 Genkit 插件生成的 `json_schema` 请求转换为该模式，并把同一 schema 注入消息；Genkit JSON parser 与本 Workflow 的结构/证据校验仍必须全部通过。该兼容分支不得变成 fenced JSON 或跨协议 transport 回退。
- batch 失败不写完成标记。取消、网络失败和进程退出保留最后一个原子 checkpoint；同范围再次生成时恢复未完成 batch。
- 结构校验失败后的重试必须携带 App 给出的具体、无正文内容的修复原因（例如父引用无效），不得用相同提示盲目重复。模型以成功终态返回但 Genkit 无法解析 JSON 语法时，也属于可修复的模型输出失败：Adapter 只负责标记异常，Workflow 在同一阶段预算内重新请求合法完整 JSON；不得在本地补标点、解 fence、截取 JSON 或接受部分节点。层级口径统一为根节点 `level=0`，子节点由 App 按父链确定层级；不要求固定最浅或最深层级。根节点多余 evidence 由 App 丢弃。模型提供的引文必须落在冻结正文范围内，成功定位后启用“跳回原文”；模型漏传、改写或无法定位引文时只丢弃该引文，不得让摘要节点或整棵树失败，也不得从正文自由猜测补证。
- 节点数、批次主题数、根分支数、同级分支数和层级深度都不设内容配额。生成提示按 `contentKind` 要求实质覆盖：论说内容包含实际存在的主张、理由、事实或例子与结论；叙事内容包含实际存在的人物或事件、动机、转折与影响；知识型内容包含实际存在的概念、定义、方法、条件与限制。没有对应内容就不补，有多少有效信息就生成多少节点；单章仍需读取正文开头、中段和结尾，整书归并不得退化成章节标题目录。
- 多内容单元的完整输入仍在单次安全预算内时直接生成，不为“多章”本身强制增加 batch/reduce。超出预算时使用更大的安全批次以减少模型往返，最终结构化输出必须原样回传全部 `coveredSections`，App 对集合做精确校验；遗漏任一冻结章节的结果视为失败并携带缺失范围重试。
- 失败、取消和成功是互斥终态。服务端拒绝结构化格式、模型输出无效或网络失败时必须显示可重试错误；只有用户明确停止才显示取消，不得无声回到未生成空态。
- 模型输出的临时 ID、布局建议和 HTML/SVG 都不可信；App 只消费结构化主题数据。

## 5. 布局与交互

支持 `radial`、`rightFacing`、`bidirectional`。新生成的导图默认使用 `bidirectional`，用户可在对话卡片或全屏画布手动切换；选择结果随同一对话附件保存，重新打开时不得被默认值覆盖。

- Flutter 原生布局 + `CustomPainter` 连线 + `InteractiveViewer`，不创建 WebView，不执行 Mermaid。节点卡片同时显示主题标题与最多数行摘要；详情页用于查看完整摘要和原文依据，不能作为摘要的唯一入口。
- 导图视觉从当前皮肤的语义主题派生，不保存为业务数据：根节点使用中性高层表面和主色结构边界，不使用明亮主题色实底配深色文字；一级分支按稳定顺序取 `primary` / `tertiary` / `secondary` 及其混合色，后代继承所属一级分支颜色。普通节点保持中性阅读卡片，只以低透明度染色、细边框和同色连线标识分支，不在节点内增加贯穿大半高度的装饰色轨，不使用 `error` 等状态色拼成固定彩虹，也不让模型决定颜色。节点阴影只使用 `AppGlassTheme.shadow × AppSkinEffects.shadowScale`，深浅皮肤均需保持边框和文字对比。
- 节点文字区分“短主题”和“正文摘要”：主题使用语义 label 字号与中等字重，摘要使用语义 caption 字号、至少 `1.4` 行高并保持三行可读；所有节点都保持中性主次文字色。装饰色不得承担唯一层级含义，层级列表与节点详情继续提供等价访问。
- 支持缩放、自由拖动、重新居中、折叠/展开分支、节点详情和从证据跳回原文。画布拖动不得在导图外 240px 等近距离设置透明边界，应允许用户把任意分支自由移到视口中心；手动缩放下限为 `0.2`，避免把内容缩到不可操作。桌面触控板两指滑动必须平移画布，双指捏合才缩放；鼠标滚轮与捏合缩放必须以当前指针位置为锚点，缩放前后指针下的场景坐标保持不变。指针位于嵌入画布内时，外层对话列表必须暂停滚动以覆盖滚轮和触控板 pan/zoom 两类事件；指针离开后恢复。对话卡片提供“全屏查看”，以独立 `Scaffold` 路由铺满 App 工作区；它共享同一结构化数据和布局选择回调，不新增 Tab 或第二份缓存。
- 画布不是唯一可访问入口。节点详情和可聚焦的层级列表提供等价操作；触控目标手机不少于 44px。
- 大图只布局可见树。折叠分支不参与坐标计算；超过性能边界时默认折叠深层并提示读者展开，不在 UI isolate 做模型或文件 I/O。

## 6. 持久化与 WebDAV

- 对话消息中的结构化 `AiBookMindMap` 附件是用户可见的历史事实，随 `ai_chat/` 会话保存；`ai_mind_map/$contentHash[.$workKey].json` 只保留该范围最近一次完成产物，供运行恢复和旧版本兼容。checkpoint 存同目录的 `.checkpoint.json`，完成后删除。
- 消息附件以各自 `scopeFingerprint` 区分，同一会话可并存多个本章与全书结果。删书不删除对话附件；同文件再导入自动续上；清空对应对话才删除其历史附件。
- 用户主动 WebDAV 快照通过对话记录包含全部已完成思维导图，并兼容备份最近产物；不包含运行中 checkpoint、API Key、模型协议连续性元数据或布局临时坐标。
- 恢复采用本地优先：本地已有合法产物不覆盖；本地没有时恢复远端。旧快照缺少 `aiMindMaps` 合法。

## 7. 实施阶段

1. 文档与业务模型：冻结边界、Schema、验证器、布局策略。
2. Workflow 与存储：预算、取消、checkpoint、错误和恢复。
3. Controller：独立状态机、对话范围路由、原子保存、WebDAV。
4. UI：对话内快捷路由和结构化结果卡片、原生画布、折叠/详情/跳转；不设置独立思维导图页签。
5. 验证：模型/存储/恢复/取消/错误、布局算法、Widget 与大图边界测试；保留聊天 Mermaid 回归测试。

## 8. 验收

- 相同结构输入的节点 ID、父子关系和自动布局确定性一致。
- 非法父引用、环、孤立节点、跨范围证据和空摘要不会被静默保存；节点多、分支多或层级深本身不是失败理由。
- 空摘要、标题复述和占位摘要不会被保存；新生成的节点卡片无需打开详情即可读到正文观点、事实、例子或结论。
- 取消后保留 checkpoint；同范围恢复不重做已完成 batch；换范围不复用旧 checkpoint。
- DeepSeek 请求使用 `json_object` 而非 `json_schema`，非法 JSON 或不符合业务约束的结果仍失败；普通失败不会被取消收尾吞掉。
- 模型第一次返回缺逗号、未闭合对象等不可解析 JSON 时，Workflow 会在既定尝试次数内重新生成完整结构；重试耗尽才显示可重试失败，且任何一次都不会保存部分导图。
- UI 可切换三种布局、折叠、宽范围缩放、无近距离边界拖动、打开详情并跳回证据；桌面缩放以指针为锚且不联动外层对话滚动；对话卡片可进入并关闭全屏画布，且全屏中的布局切换会保存回同一对话附件。
- 失败轮次点击重试时原位替换该轮，不追加重复用户消息。全屏中的证据跳转依次关闭节点详情、全屏画布和 AI 工作区，最终露出已经定位的阅读正文。
- 对话内与全屏画布共享同一主题派生视觉：同一一级分支及其后代使用一致标识色，不同一级分支可区分；切换浅色、深色、皮肤或强调色后重新派生，不写入或污染 `AiBookMindMap`。
- WebDAV 能导出/恢复已完成思维导图，旧快照仍可解析，Key 与 checkpoint 不进入快照。
- 普通聊天 Mermaid mindmap 和其他图表继续渲染，且不读取 `AiBookMindMap`。
