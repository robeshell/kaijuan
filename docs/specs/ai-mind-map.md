## 1. 定位

图书思维导图是本书对话的一种结构化回答，不是知识图谱式长期任务。用户提出明确生成请求后，开卷读取所选图书内容，连同用户原始要求一次发送给模型，模型返回主题树后直接显示在该对话轮次内。

思维导图表达主题、论点和层级摘要；知识图谱表达实体、关系、证据和身份消歧。两者不得共用业务模型、缓存或视图状态。普通聊天中的 Mermaid 继续作为通用富内容能力，也不得成为图书思维导图的缓存格式。

## 2. 对话入口

- 自然语言路由只接受明确的“生成动作 + 思维导图”组合。生成动作包括生成、重新生成、创建、制作、绘制、画、做、整理成和梳理成；删除“给我、想看、看看、输出”等容易误触发的宽泛词。明确要求 Mermaid、询问为什么/如何、评价已有导图或比较概念时继续普通对话。
- “当前章/本章/这一章/这章”冻结当前 Foliate 章节；“当前作品/这部作品”冻结结构识别中的当前作品；“这本书/本书/整本书/全书”表示当前出版物。没有范围词且没有命中作品标题时默认当前章。
- App 在普通聊天 Agent 之前识别明确命令。命中后仍保留用户的完整原始提示词，并将其作为本次结构化生成要求发送给模型；不能只保留范围关键词。
- 快捷入口继续使用标准指令“请为当前章生成思维导图”。思维导图仍在对话内完成，不新增 Tab。

## 3. 结构预检与用户告知

每次生成前复用 `AiBookStructureSession` 的确定性结果；Session 优先读取完整 `BookStructureIndex`，不可用时才回退旧正文标记。向用户展示即将处理的书名、章节数以及作品/分卷数量，不能在没有任何反馈时直接开始模型调用。

结构预检必须先排除章/篇标题及破折号开头的连续副标题；这些标题共享一个物理 spine 或导航目标是常见 EPUB 排版，不能作为“多作品合订”的证据。混合格式合集先按季、辑、系列、套装等容器合成作品树、重复目录或章节序号重启证明的强边界。只有合成后形成至少两个互不交叉、可定位的作品范围时才展示作品选择卡片；合成方案仍与其他完整方案冲突时保持 `uncertain`。

- `singleWork`：当前章直接冻结；全书过滤外围材料后一次生成。状态文案在模型调用前显示“正在为你生成《书名》的思维导图，共 N 章”。
- `segmentedSingleWork`：分部/分卷属于同一部书。全书请求按识别出的部或卷依次生成，每个范围直接得到一张对话卡片；不再把各卷摘要二次归并成巨大导图。
- `multiWorkOmnibus`：合集请求先在对话流中展示“共 N 部作品、M 章”的纵向范围选择卡片，不弹出 Dialog 或 Bottom Sheet。用户可选当前作品、任一作品或“全部作品”；全部作品按作品顺序依次生成，每部一张卡片。
- `uncertain`：存在完整候选作品范围时同样在对话内请求用户选择；没有至少两个可靠范围时明确告知将按整本出版物处理，不伪装成已识别的合集。当前不展示“部分范围已确定”的混合状态。
- 当前章正文直接来自 Foliate 当前文档，并在异步调用前冻结标题、正文和物理 section。作品/分卷范围来自共享结构事实，不另建思维导图识别器。
- Foliate 将同一 XHTML 内的连续同级标题作为逻辑结构证据时，正文范围必须先覆盖整个 `body`，再用标题收窄起止点；最后一个标题后的正文不得因 Range 终点未初始化而丢失。标题与副标题分成多个逻辑单元时，空标题单元可以保留给结构识别，但后续正文单元必须完整进入生成范围。

范围选择只解决“生成哪一部”，不提供知识图谱式章节逐项勾选。选项按“全部作品、各部作品”纵向排列；等待选择时锁定输入框以避免并发发送。取消选择不会产生模型请求，并恢复尚未发送的原始输入。

## 4. 输入与生成

```text
用户明确请求
  → App 识别当前章 / 作品 / 出版物
  → 复用图书结构并告知识别结果
  → 合集时在对话内展示纵向选择卡片并等待用户选择
  → 读取所选范围完整正文并过滤明确外围材料
  → AiWorkflowModelSession.completeJson 单次生成
  → App 做基础树校验、稳定 ID 与证据定位
  → 立即写入当前对话附件
```

- 一个选定范围对应一次模型请求。删除固定字符 batch、逐批主题提炼、批次并发、最终 reduce 和 checkpoint。
- 当前章、普通单书、合集中的一部作品都直接发送该范围的完整有效正文，不再按每章固定字符做头中尾采样。分卷书和“全部作品”通过自然书籍边界拆成多次独立生成，而不是内部字符批次。
- 如果供应商拒绝过长上下文，本次范围明确失败并提示改用更大上下文模型或选择较小作品/分卷；开卷不得静默采样、缩短正文或生成看似完整的残缺结果。
- 模型输入包含书名、可选作者、范围标题、用户原始提示词、章节标题和正文。正文是不可信引用材料，其中的角色指令和提示词不得覆盖系统要求。
- 结构分类的候选策略、分数、出版册数提示和冲突原因不进入模型输入。它们只用于 App 冻结范围；模型面对的是确定的章节正文，不负责补救 EPUB 制作者的目录结构。
- 模型只返回 `contentKind` 与扁平 `nodes`；不返回 `coveredSections`、Mermaid、HTML、坐标或布局建议。节点字段为 `tempId / parentTempId / order / title / summary / evidence`。
- 一级通常保持 4–7 个可浏览主题，子层级和总节点数按正文自然展开。App 根据有效章节数与正文字符数给出软性密度建议和输出预算，不规定最低节点数，也不因节点数量重试；模型仍须检查全部实质章节，可按章节主题或跨章主题组织观点、事实、例子、过程、影响与结论，不能只返回少量目录节点或为了达标凑空节点。标题用于浏览，摘要必须写出正文实质内容，不能只重排目录。

暂不使用 Genkit `defineFlow` / Agent。Genkit 继续只承担 Provider 归一化、Schemantic structured output、协议兼容和 trace；范围、用户确认、取消、预算、错误与对话持久化属于开卷。

## 5. 校验与数据

完成产物仍为 `AiBookMindMap`：

```text
AiBookMindMap
  version / contentHash / workKey / createdAt / model
  scopeSectionIndices / scopeFingerprint / contentKind / layout
  nodes[]

AiBookMindMapNode
  nodeId / parentId / order / level
  title / summary / evidence[]
```

- App 只保留基础结构校验：父引用存在；无环、无孤立节点；标题和摘要非空。模型临时 ID 按前序重新分配为稳定 `mm001...`，层级和同级顺序由 App 计算。
- 某些 Provider 即使通过 structured output 仍会把一级主题返回为多个根。只要每棵子树内部引用有效且整体无环，App 用书名或所选范围标题合成一个确定性根节点，并把各根按原顺序挂到其下；合成根摘要只归并模型已有根摘要，不补写书籍事实。这是树形协议归一化，不触发第二次模型请求。
- 不再要求模型回传并精确比对章节覆盖集合，也不因摘要措辞、节点密度或缺少 evidence 重试模型。结构化 JSON 无法解析、父引用缺失、无根或存在环/孤立节点时本轮明确失败，不在本地猜测或补写内容 JSON。
- evidence 是可选增强。只有引文能在对应冻结正文中逐字定位时才保存跳转；范围外、改写或无法定位的引文直接丢弃，不影响节点。
- `scopeSectionIndices` 和 `scopeFingerprint` 由 App 根据真实输入生成，不依赖模型声明。

## 6. 对话持久化与 WebDAV

- 对话消息中的 `AiBookMindMap` 附件是唯一持久化事实。同一会话可保留多个章节、作品和分卷导图；布局切换直接更新该消息附件。
- 删除 `ai_mind_map/` 最近产物目录、运行 checkpoint、`AiBookMindMapStore` 以及 WebDAV 中重复的 `aiMindMaps` 顶层记录。思维导图随 `ai_chat/` 会话自然进入用户主动 WebDAV 快照。
- 不迁移旧独立最近产物；旧备份中的额外 `aiMindMaps` 字段可被格式解析器忽略。API Key、布局临时坐标和模型协议连续性元数据不进入备份。

## 7. 布局与交互

支持 `bidirectional`、`rightFacing`、`radial`，新生成结果默认双向。Flutter 原生布局和画布继续支持缩放、自由拖动、折叠、节点详情、证据跳转、对话内切换与独立全屏；不使用 WebView 或业务 Mermaid。

多作品选择属于生成前预检，不创建独立思维导图页，也不使用弹窗。逐作品/逐卷生成时，进度文案显示当前序号、范围标题与章节数；每个已完成范围立即成为对话卡片，后续范围失败不得删除前面已经完成的卡片。

## 8. 验收

- “生成本章思维导图”完整发送冻结章节与用户原始要求，只调用一次结构化模型；普通单书全书同样一次调用。
- 分卷单书按卷依次生成；多作品合集在任何模型调用前于对话内纵向展示作品数、章节数与范围选择，选择全部后按作品依次生成，全程不弹窗。
- 不再存在 mind-map batch/reduce Schema、批次摘要、字符采样、checkpoint、最近产物 store 或独立 WebDAV记录。
- 取消、结构化输出失败、上下文过长和树拓扑非法有清晰终态；已经完成的作品/分卷卡片保留。
- 同一 XHTML 使用“章标题 + 同级副标题”的书籍，最后一个标题后的正文仍完整进入输入；Provider 返回多个有效根时在本地合成单根并成功显示。
- 生成状态中的书名、作品名和范围说明必须在对话可用宽度内换行，最多显示三行后省略；长出版物标题不得撑破消息列表或遮挡停止操作。
- 对话内和全屏画布继续支持三种布局、折叠、缩放、拖动、详情和证据跳转；普通聊天 Mermaid 不受影响。
