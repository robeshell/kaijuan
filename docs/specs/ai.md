## 1. 结论（先读）

**开卷 AI = 围着一本书的可选智能体**，不是全局聊天 Tab，也不是账号云。

| 层 | 职责 | 网络 |
|----|------|------|
| 设置 / BYOK | Key、端点、模型、总开关 | 仅用户主动「测试连接」或功能调用时 |
| 语言工具 | 词典、选区翻译（实现 `BookLanguageProvider`） | 有 Key 且 AI 开时出网；否则系统能力 |
| 本书工作区 | 对话、大纲、任务（整本译等） | 同上 |
| 沉淀导出 | Markdown / Obsidian 单向导出 | 本地文件 I/O；不经过模型托管 |

与听书 **解耦**：TTS 继续系统语音（[book-tts.md](./book-tts.md)）；本 spec **不做** 云端 AI 音色。

与 WebDAV 凭据 **隔离**：AI 对话历史随用户主动执行的 WebDAV 备份同步；**API Key 永不进入备份清单**（同 WebDAV 密码策略）。

### 当前实现状态

已完成：

- BYOK 设置、总开关、OpenAI 兼容协议、Anthropic、DeepSeek 和连接测试。
- 选区 AI 词典与翻译，支持系统能力 fallback、流式输出、停止、复制和上下文前后文。
- 本书对话，按 `contentHash` 持久化，支持当前章节、选区、目录、全文取样和书内检索工具。
- 对话正文流式输出、工具执行状态、停止、复制、清空，以及有限历史和请求重试。
- AI 对话纳入用户主动执行的 WebDAV 备份；恢复时按书籍 `contentHash` 合并并去重。
- 本书 AI 工作区提供对话 / 大纲 / 知识图谱 Tab；大纲按可读单元分批生成、显示进度、可停止、可展开阅读、可跳转、可重生成或删除。
- 大纲按 `contentHash` 与对话共同缓存；手动 WebDAV 快照会备份并恢复大纲，Key 仍不备份。

规划中：

- M4：按章或整本翻译任务。
- M5：人物、地点、事件知识图谱。
- M6：Markdown / Obsidian 单向导出。

待定：

- 多对话管理。当前继续使用“每本书一个对话”，不改变划线提问的现有行为。

明确取舍：

- 本书对话继续使用 fenced JSON 工具协议，不引入原生 API tool-call、LangChain 或其他 Agent 框架。

## 2. 目标与非目标

### 做

- 用户自备 Key；内置预设 **OpenAI / Anthropic / DeepSeek**，另支持自定义 OpenAI 兼容端点。  
- 总开关：关 = 零 AI 网络请求。  

- 选区 **AI 词典**、**AI 翻译**（应用内结果，可流式）。  
- **本书对话**（绑定当前书；静默带当前位置 + 可选选区；快捷问法）。  
- 后续：大纲、按章/整本翻译任务、知识图谱、知识库导出（见 §9 切片）。  

### 不做（本能力内）

- 第四根根 Tab「AI」。  
- App 托管模型、代扣费、强制账号。  
- 默认上传整本/整库；无用户动作自动出网。  
- 对未来的大纲等任务默认不读取未读内容；本书对话当前不按阅读进度裁剪。  
- 漫画 OCR / 气泡翻译（远，另案）。  
- 云端 AI 听书音色。  
- Obsidian 双向实时同步（导出可为单向）。  
- 把 prompt 拼装、HTTP、Key 读写放进 Widget。

## 4. 交互

### 4.1 设置（M0）

页面分组（与备份页同样：分组间距 ≥ 组内两倍）：

1. **总开关**  
   - 「启用 AI」：关时下方表单项 disabled 或仍可编辑但不请求。  
   - 副文案：「使用你自己的 API Key；密钥只保存在本机。」  

2. **连接**  
   - API Key：安全输入（可显隐）；保存进平台安全存储。  
   - 接口地址：默认占位如 `https://api.x.ai/v1` 或留空提示「兼容 OpenAI 的 Base URL」。  
   - 模型：文本框或近期列表；不内置付费套餐 UI。  
   - 「测试连接」：发最小 completion；成功 SnackBar「连接正常」；失败展示可读错误。  

3. **联网搜索（可选，BYOK）**  
   - 服务商：Tavily / Brave Search。  
   - 搜索 API Key：与模型 Key 分开，进安全存储，**不进** WebDAV。  
   - 仅当用户在本书 AI 面板打开「联网」时才会请求搜索 API。  

4. **阅读偏好**  
   - 「允许未读上下文」：控制大纲范围。关 = 只处理当前章节及之前的正文；开 = 处理全书。**本书对话不按进度裁剪**。  

文案原则：不承诺具体供应商名称作为唯一后端；不展示「免费额度」类托管话术。

### 4.2 选区结果卡（M1）

```text
用户选区 → 点「词典」或「翻译」
  → 若 AI 关或无 Key → 现有系统路径（PlatformBookLanguageProvider）
  → 若 AI 可用 → 关闭动作条（或保留）→ 打开结果卡
       流式正文
       底栏：复制 | 写入笔记（可选）| 关闭
```

**词典卡**

- 标题：词/短语截断一行。  
- 正文：释义、词性、简短例句（模型输出；失败时短错误 +「使用系统词典」次级按钮）。  
- 「写入笔记」：若当前无划线，先按默认样式创建划线再写 note；已有划线则追加/写入 note 字段（产品定一种：覆盖确认 or 追加分隔）。  

**翻译卡**

- 权威规范见 **[ai-translation.md](./ai-translation.md)**（目标语言、方向、风格、结果卡本次覆盖）。  
- 原文折叠（默认收起一行，可展开）。  
- 译文流式 + 分段排版（`AiResultBody`）。  
- 默认目标语言：**简体中文**；方向：**固定译到目标语言**。  

结果卡不得挡住整页到无法关；点遮罩或关闭即 dismiss；进行中关闭 = 取消请求。

### 4.3 本书对话（M2）

```text
阅读器 →「本书 AI」
  → 呈现（自适应）
       · compact 手机：底 sheet（高约满屏可滚）；底部始终避开手势区 / Home indicator，键盘弹出时以键盘 inset 为准
       · medium / wide：右侧侧栏，宽度随窗口变（约 40–48% 宽，有 min/max）
  → 顶栏：本书 AI 与关闭 / 清空操作；Tab：对话 / 大纲 / 知识图谱
  → 书名、当前章不在面板顶部重复展示；阅读器本身已提供该上下文
  → 输入工具栏：紧凑「联网」图标（关=仅书内；开且已配搜索 Key=先搜再答）；开启时保留搜索图标，以主题色高亮和轻量底色表示状态，不替换为勾选图标；另有可去掉的选区附件
  → 推荐问题（每处至多 3 个）：空对话给阅读入口；有选区时改为解释选段 / 联系上下文等；每条助手回答完成后生成两条稳定追问和一条内容发散追问，并在生成完成后一次性显示；失败时一次性回退三条稳定问题，不先展示再替换。显示后消息列表自动滚至底部。左对齐纵向排列，文字尾端以箭头提示可直接提问
  → 等待态：消息列表内同一时刻只展示一个小尺寸思考球与一行状态；优先级为联网搜索、工具执行、模型思考。联网完成后更新为「联网完成，思考中」，不叠加第二个等待提示
  → 消息列表 + 输入框
  → 流式助手气泡；工具状态；停止；复制；清空
```

**定位：整本书的阅读伴侣（不设剧透策略）**

- 对话可讨论全书情节、人物与主题；**不**按阅读进度裁剪「能不能说后文」。  
- 设置里的 `allowUnreadContext` **不作用于本书对话**。  

**联网（面板开关，默认关）**

| 状态 | 行为 |
|------|------|
| 关 | 不调用搜索 API；模型仅依据书内取样 |
| 开 + 有搜索 Key | 发送前用用户问题（附书名）检索 Top 条摘要 → 注入 prompt「Web search results」；回答结构优先【书中】再【补充说明】并简述来源 |
| 开 + 无 Key | 提示「请先在设置中填写联网搜索 Key」并引导去设置 |

- 搜索失败：本轮中止并展示错误；不静默退回无网回答（避免用户以为已联网）。  
- 搜索 Key 与模型 Key **独立**；总开关关时仍可先填搜索 Key，但对话不可用。  
- 等待动画使用 `thinking_orbs` 的 inline 尺寸：搜索、工具与思考分别使用对应状态；系统要求减少动态效果时由组件显示静态帧。

**正文怎么进模型（轻量 tool，不默认灌全书）**

| 层 | 内容 | 作用 |
|----|------|------|
| 划词 | 用户选中原文 | 问题锚点（种子） |
| 当前章 | 正在读的一节（种子，有上限） | 多数局部问题够用 |
| 目录标题 | `tocOutline` / tool `get_toc` | 结构索引 |
| **Tools**（模型按需调用） | `get_current_chapter` / `get_chapter` / `search_book` / `sample_book` | 取其它章、关键词、全书均匀取样 |
| 网页摘要 | 面板「联网」开时 | 书外通识；回答【书中】+【补充说明】 |

协议：模型需要更多正文时，只输出 fenced JSON：

```kaijuan_tools
[{"name":"sample_book"},{"name":"search_book","query":"张居正"}]
```

App 执行 tool → 把结果塞回对话 → 最多约 4 轮 → 再流式正文回答。  
**不引入 LangChain**；自研协议，便于以后接大纲/图谱任务。

例 1：快捷「这本书在讲什么」→ 提示模型用 `sample_book` → 按全书取样答。  
例 2：划词 +「为什么现在」→ 种子选区 + 可选 `search_book`。  

- 有划词：附件芯片可 × 去掉。  
- **推荐问题**：空对话与选区状态直接发送预设的书内问题，各显示 3 个；助手回答完成后显示 3 个继续追问入口，流式输出、工具执行或出错时不显示。回答后的三条采用 **2 条稳定阅读追问 + 1 条本轮专属发散问题**：专属问题由模型在正文结束后，以用户问题、最新回答、当前选段/章节为依据做一次短 JSON 请求生成；成功后替换一条稳定入口并随该助手消息存盘，失败、取消或关闭面板时保留稳定入口，不影响正文回答。每项独占一行、文字末端带箭头，不另设分组标题。  
- 面板是阅读器工具面板，不把标题、书名、章节和控制重复堆在固定区域。助手回复以阅读正文的留白和行高为主，用户消息才用轻量强调色承载；生成状态、工具状态和错误保持紧凑且临近对应内容。手机上的面板采用独立紧凑字号：面板与大纲区标题 16px，对话正文和章节标题 15px，概览、展开详情、要点与 Tab 14px，收起条目的摘要预览与辅助标签才使用 caption。列表行、概览区、快捷问法和消息间距同步收紧；每条完成的助手回复末尾仅保留有 tooltip 的紧凑复制图标，不显示文字按钮；输入框仍显式使用 16px input，避免 iOS 聚焦缩放。
- 桌面输入框：Enter 在**没有输入法组合文本**时发送，Shift+Enter 换行；组合输入期间（中文、日文、韩文等候选词确认）一律交回系统输入法处理，不拦截 Enter。手机仍使用键盘的发送动作。

**回答规范（进 system）**

- 优先依据 tool / 当前章正文；书外通识标「补充说明」。  
- 不编造书中未出现的情节；与书无关的纯作业可婉拒。  
- **用户可见文案**：正文不足时用「根据目前能看到的正文」；**禁止**「已收录」等实现黑话。  


- 会话按 **本书 contentHash** 持久化；v1 不做跨书列表。  
- 空态：`围绕这本书聊聊：总结、人物，或你想到的问题。`  




### 4.4 大纲（M3）

```text
本书 AI → 大纲
  → 未生成：说明生成后缓存本书 +「生成大纲」
  → 生成中：当前章节批次进度 +「停止」
  → 已生成：受控长度的全书概览、可展开的单元摘要与要点
       → 首屏概览：默认三行；段落末尾的向下 / 向上箭头展开或收起完整概览，主题不占默认首屏
       → 收起条目：标题、一行摘要和一个展开操作，供快速扫读
       → 展开条目：摘要只在此处出现一次；默认显示受控长度的摘要与要点
       → 节点内容后：放置前往原文、生成 / 刷新下级和完整内容展开操作
       → 点完整内容图标：显示该节点全文和全部要点；不影响树节点的展开状态
       → 前往原文：位于展开内容后的有提示图标，跳转后关闭面板
       → 概览标题旁：重新生成；更多：删除大纲
```

- 生成是一次显式任务，结果不会因关闭面板而取消；读者主动停止或退出阅读器才取消。
- 先由本地规则过滤标题或正文中可确定的目录、版权等元数据页；若电子书把整部合集放进单一 spine XHTML，则先按重复 HTML 标题切为逻辑单元；对 AZW3/MOBI 等有导航目录的文件，优先解析目录项的跳转位置并合并其覆盖的连续 spine section，避免让模型从数百个碎 section 猜作品边界。导航单元只按其标题识别目录、版权等元数据，不能因正文开头有作品内目录而被丢弃。跨 WebView 的大纲语料按导航单元均分预算，并保留每个单元的头尾，不能由全书前部耗尽上限。逻辑单元保留原 spine 跳转锚点。若已取得不超过 24 个具名导航单元，直接逐单元摘要；否则模型依据逻辑单元标题和短样本创建结构计划，把普通书的章节或长合集的作品/分卷组织为单元。App 严格校验计划：每个输入 section 必须恰好归入一个单元或明确忽略，不能有未知或重复索引；无效计划会逐节回退，不会静默遗漏正文。大纲正文读取上限为 150 万字符；每个单元再取最多约 3600 字的代表性正文样本，最多四个单元一批请求摘要，最后根据单元摘要生成全书概览；摘要漏单元或 JSON 无效不保存缓存。
- 大纲是可按层下钻的树，而不是按书名猜测“合集”或“普通书”。展开一个节点只显示已有摘要；读者点「生成下级大纲」后，才在该节点真实 spine 范围内生成子节点：先使用原生目录的直接子项及其跳转位置；没有可用子目录时，再使用正文标题；仍无结构时，才以该范围的语义切片作为候选。模型只负责摘要和命名已确定的候选范围，不能创造跳转边界。候选超过 12 项时，先由模型依据标题和短样本把连续的已确定范围整理为每组至多 8 项的中间节点，首轮即可展示；再展开中间节点才逐项摘要，避免一次展开几十项而产生十余次串行请求。失败后同一位置提供「重新生成下级大纲」，已生成的分支也可手动刷新。子节点随父节点写入同一份 `contentHash` 缓存，重新打开面板不会重复请求；模型结果先显示，再异步落盘；首次生成只处理顶层。
- 大纲缓存包含生成算法版本；算法升级后的旧缓存不会继续显示，读者可从可见的重新生成按钮创建新缓存。
- 全书大纲始终使用全书正文；它是显式生成并缓存的整书阅读辅助，不会因当前阅读位置退化为「已读章节」大纲。`allowUnreadContext` 不作用于本书对话或大纲，留给后续需要防剧透的功能。
- 大纲不流式输出结构化 JSON，但界面持续显示分批进度；正文对话仍独立走流式请求。
- 知识图谱 Tab 仅保留入口和占位，尚未生成或缓存图谱。
- 大纲页面是内容密集的阅读工具，不使用卡片套卡片。面板表面保持不透底，保证书页文字不会干扰大纲阅读。默认首屏按扫读密度呈现：全书概览最多三行，不直接显示主题；段落末尾的上下箭头按需展开或收起完整概览，每个收起节点最多一行摘要。完整概览和全部要点由有 tooltip 的图标按需展开。树节点仅用稳定缩进表达父子关系，不画连接线或强调色竖线；展开箭头提供唯一的层级提示。收起条目显示摘要预览，展开后不重复该预览。节点内容底部只保留一条紧凑动作栏：初次「生成下级大纲」可用文字操作；完整内容展开、已有分支刷新和前往原文并列为有 tooltip 的图标。单一原始 section 的已知末级，以及已确认没有子节点的末级，仅保留前往原文，不显示生成或刷新下级入口；读取失败时仍可重试。错误紧邻动作栏；展开树只披露已有内容，绝不隐式触发模型请求。

### 4.5 后续切片交互（纲要）

| 切片 | 入口 | 要点 |
|------|------|------|
| M3 大纲 | 本书 AI 面板 Tab 或目录旁 | 树状列表；点节点跳 CFI/章；「重新生成」 |
| M4 整本/按章译 | 语言菜单 / 本书 AI 任务 | 进度条、可暂停取消；按章缓存 |

## 7. 数据、安全与分层

### 7.1 分层（建议）

```text
presentation/
  settings AI 子页、结果卡、本书 AI 面板
  → AiSettingsController / BookReaderController（或 AiBookController）
lib/ai/   （ENGINEERING 落地时挂树）
  settings/     # 开关、endpoint、model；Key 只经 SecureStore
  provider/     # AiProvider：chat / stream / testConnection
  context/      # 从书抽选区、章、已读范围；截断与 token 预算
  features/
    language/   # AiBookLanguageProvider implements BookLanguageProvider
    chat/
    outline/    # M3+
    jobs/       # M4+ 长任务
    graph/      # M5+
    export/     # M6+
  cache/        # contentHash + feature + inputHash → 结果
```

约束：

- UI **不**持有 `http.Client`、不读 Key、不拼系统 prompt。  
- `BookReaderController` 继续是选区菜单入口；语言请求走 `BookLanguageProvider`，AI 实装替换/组合 Platform 实现。  
- 整本译等长任务用 job 状态机，不堵 UI isolate 上的同步大循环。  

### 7.2 上下文装配

| 模式 | 装入 prompt 的内容 | 备注 |
|------|-------------------|------|
| 选区 | 选区文本 + 可选前后各 ≤N 字 | 词典/翻译/对话 |
| 当前章 | 当前 spine/section 纯文本（截断） | 对话/大纲章级 |
| 已读范围 | 当前进度之前的章：优先用缓存摘要，否则切片 | 仅供未来大纲等任务；本书对话当前不使用 |
| 全书 | 仅用户明确开启 | 设置项，默认关 |

一律附带：书名、可选作者；**不**附带其他书的内容。

### 7.3 持久化

| 数据 | 存储 | 进 WebDAV 备份？ |
|------|------|------------------|
| API Key | 安全存储 | **否** |
| endpoint / model / 开关 | 偏好或 DB 用户设置 | 否（或仅非机密偏好，Key 仍否） |
| 对话历史 / 本书 AI 记忆（含未来钉选） | 按 **contentHash** 本地文件（如 `ai_chat/`） | **是**（用户主动 WebDAV 快照）；不含 Key |
| 词典/翻译缓存 | 可选本地 cache 表 | 否 |
| 划线 note（用户确认写入） | 现有 annotations | **是**（已有备份范围） |
| 大纲 | `ai_chat/` 下按 contentHash 的会话文件 | **是**（用户主动 WebDAV 快照） |
| 图谱 / 译稿 | 本地 cache + contentHash | 未做；导出后是用户文件 |

#### 身份与删书再导入（已定）

- **主键是 contentHash**（文件内容指纹），不是书库行 `itemId`。  
- **删书库条目不删除** `ai_chat` / 本书 AI 记忆文件。  
- **同一文件再导入**（hash 不变）→ 对话与钉选/记忆**自动续上**；打开时用新 `itemId` 写回会话元数据即可。  
- **文件内容变了**（hash 变）→ 新书、新会话。  
- **用户点「清空对话」** → 只清该 hash 的会话，不删书。  
- 卸装 / 清 App 数据 → 本地记忆一并没（已做用户主动 WebDAV 快照时可恢复）。

AI 对话备份规则：

- 对话与大纲先实时保存到本地；返回阅读器其他页面不会自动上传。
- 用户手动执行 WebDAV 备份时，`ai_chat/*.json` 中对应书籍的历史和大纲随快照上传。
- 恢复只处理备份中仍能匹配到的书籍；本地已有消息按 JSON 去重合并，本地已有大纲优先，不覆盖本地内容。
- API Key、搜索 Key 和 WebDAV 凭据均不备份，恢复后需要在目标设备重新配置。

### 7.4 网络与隐私

- 仅用户触发的动作发请求。  
- 请求体含用户选段/章节文本时，设置页应用简短隐私说明：「正文片段将发送到你配置的接口地址」。  
- 不写第三方分析 SDK 专打 AI 事件（若全局无，则 AI 也不例外加）。  
- 防提示词注入：system message 仅包含应用固定规则、工具目录和联网回答格式；书名、目录、选区、正文、网页摘要及工具结果都作为带 `<untrusted_context>` 边界的引用材料传入，材料中要求改写规则、调用工具、泄露数据或改变角色的文本一律不可执行。工具调用只接受模型整条回复为 `kaijuan_tools` fenced JSON block；普通回答、书中文字或一般 `json` 代码块绝不触发工具。白名单、参数限制和最多四轮工具调用继续生效。

## 8. 与现有契约的衔接

### 8.1 `BookLanguageProvider`

已有操作：

- `dictionary`  
- `selectionTranslation`  
- `fullBookTranslation`（平台实现返回 unsupported；AI 在 M1/M4 接）  

M1 行为：

```text
AiBookLanguageProvider（或 Composite）
  if !aiEnabled || !hasKey → PlatformBookLanguageProvider
```

注意：当前 `BookLanguageActionResult.content` 为一次性字符串；流式需要在 controller 层增加 **stream 会话**（例如 `Stream<String>` / chunk 回调），不硬塞进同步 `execute` 返回值。可选：

- A：`execute` 仍用于系统路径；AI 路径 controller 调 `AiProvider.stream` 另开。  
- B：扩展 Provider 接口增加 `streamExecute`。  

**推荐 A**（少改菜单协议）：菜单仍调 controller 方法；controller 内分流。

结果从「外跳」变为「可应用内」是增强，不是新按钮。

### 8.3 听书

本 spec 不修改 TTS 路径；禁止为听书复用 AI Provider。

## 10. Provider 约定（实现备忘）

- 兼容 **OpenAI 风格** Base URL（`/chat/completions` 或文档当时推荐的 responses API；实现时以所接服务商文档为准）。

- 模型名用户自填；App 可提供「常用占位」但不锁死。  

默认文档示例可用 xAI 兼容端点（`https://api.x.ai/v1`），**不**在 UI 写死为唯一选项。
